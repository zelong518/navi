# arxiv 筛选方向（模板）

复制成 `$NAVI_HOME/arxiv-directions.md` 再按自己的关注点改。**这份文件是你唯一需要维护的**——
加/删方向、调松紧都在这里，不用改 skill 或代码。`navi-arxiv` 每次筛选前会读它。

判断**理解主题**，不要只做关键词匹配。一篇论文**只进一个方向**，按「最贴近其主要贡献」的那个。

---

## 一、大语言模型基模

**收**：架构创新、预训练、后训练/RL、推理能力（reasoning）、上下文长度、多模态基座、
数据配方、scaling law、模型评测方法。

**不收**：纯应用（把现成模型用在某个垂直任务上且无方法贡献）。

**边界**：alignment / RLHF 类**只在动机是提升能力**时归这里；动机是安全性（无害、拒答、
防操纵）的归「大模型安全」。

## 二、训练系统

**收**：服务于大模型**训练**的系统工作——并行策略（TP/PP/EP/CP）、通信与集合通信优化、
显存与重计算、调度与弹性、数据管线、检查点、RL 训练框架与 rollout 基建、训练稳定性
（loss spike / 数值问题）。

**边界**：只是通用分布式系统、与大模型训练无关的 → 归「相关系统方向」。

## 三、推理系统

**收**：服务于大模型**推理 / serving** 的系统工作——KV cache 管理与卸载、批调度与
连续批处理、投机解码 / MTP、量化与稀疏化部署、算子与 kernel、长上下文推理、
分布式 serving 与 PD 分离、成本 / 延迟 / 吞吐优化、推理侧世界模型或 agent 的执行开销。

**边界**：与「训练系统」的分界是**服务于训练还是服务于推理**；同时涉及两者时看主要贡献
落在哪一侧。纯算法层面的效率改进（不涉及系统实现）归「基模」。

## 四、可靠性与故障观测

**收**：面向**运行时可靠性与可诊断性**的工作——故障检测 / 定位 / 根因分析、可观测性
（trace / metric / log / profiling）、异常检测、hang 与静默错误（SDC）、
容错与故障恢复、检查点与重启代价、SLO / 稳定性保障、混沌工程、
大规模训练或推理集群的失效分析与实测报告。

**边界**：判断依据是**是否针对（大模型或其基础设施的）运行时可靠性**。
通用软件缺陷预测、代码 bug 修复、静态分析 → 归「相关系统方向」，除非明确面向 LLM 系统。
与「推理系统 / 训练系统」同时命中时：主要贡献是「更快 / 更省」归系统方向，
「更可靠 / 更可诊断」归本方向。

## 五、大模型安全

**收**：攻击、防御、评测，**且对象是大模型或 agent**——越狱与提示注入、后门与投毒、
对齐鲁棒性、agent / 工具 / MCP 的攻击面、GUI agent 安全、模型窃取与水印、
安全评测基准、安全漂移审计。

**不收**：传统软件漏洞、通用密码学、与模型无关的网络安全。

## 兜底：相关系统方向（非面向 LLM）

上面五类没命中，但属于**通用训练 / 系统 / 可靠性**方向的论文——**不要丢弃**，
